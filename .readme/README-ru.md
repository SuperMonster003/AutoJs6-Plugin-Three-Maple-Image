### Введение

******

Image Tools - это плагин обработки изображений для файлового менеджера AutoJs6. После включения у каждого файла изображения в файловом менеджере появляются два действия в дополнительном меню: `Редактировать изображение` открывает редактор с холстом и панелью инструментов для повседневных правок (обрезка, поворот, цветокоррекция, рисование), а `Преобразовать изображение` открывает диалог, который сохраняет изображение в JPEG, PNG или WebP, при желании изменяя его размер.

Результат всегда сохраняется как новый файл рядом с исходным (его имя получает суффикс `edited` или `converted`). Исходный файл все время остается доступным только для чтения и никогда не изменяется, не перезаписывается и не удаляется. Плагин не запрашивает разрешений на хранилище и сеть и может обращаться только к одному входному файлу и одному месту вывода, разрешенным хостом.

******

### Основные возможности

******

- Редактор предлагает предустановки обрезки, поворот на 90 градусов и точный поворот от -45° до +45°, отражение по горизонтали и вертикали, яркость, контрастность, насыщенность, цветовую температуру, кисти и стилизованный текст с живым предпросмотром.
- Типы кисти включают карандаш, маркер, мозаику для приватности и ластик с запоминанием цвета и толщины; текст поддерживает несколько строк, размер, цвет, контур, тень и размещение перетаскиванием.
- Отмена и повтор сохраняют до 8 снимков истории в пределах 192 MiB; `Восстановить оригинал` тоже можно отменить, а выход с несохраненными изменениями требует подтверждения.
- Диалог сохранения редактора может следовать исходному формату или выбрать JPEG, PNG либо WebP, настроить качество с потерями и включить WebP без потерь на Android 11+; хост публикует новый соседний файл, не перезаписывая источник.
- Конвертер поддерживает JPEG / PNG / WebP, качество 1-100 (по умолчанию 92), целевой размер для JPEG и WebP с потерями, WebP без потерь на Android 11+ и автоматическую индексированную оптимизацию PNG для изображений не более чем с 256 цветами.
- Четыре режима размера: `Исходный`, `Процент` (1-1000), `Пользовательский` с фиксацией пропорций и `Длинная сторона` (по умолчанию 1920 px, без увеличения); JPEG может заполнять прозрачность белым или черным.
- Диалог в реальном времени показывает разрешение и ожидаемый размер. Безопасное сохранение EXIF по умолчанию выключено; при включении оно оставляет ограниченные поля камеры, нормализует ориентацию и всегда удаляет GPS и встроенные эскизы.
- Изменения конфигурации сохраняют холст, черновики, историю отмены/повтора и выполняющиеся задачи; каждое действие по-прежнему использует один ввод только для чтения и одну одноразовую соседнюю транзакцию вывода, принадлежащую хосту.

### Установка и использование

******

Перед началом проверьте следующие требования:

```text
host app: AutoJs6 (org.autojs.autojs6)
minimum host build: 5269
minimum android: 7.0 (API 24)
plugin package: io.github.supermonster003.autojs6.plugin.imagetools
```

От установки до первого обработанного изображения всего 4 шага:

1. Скачайте и установите APK плагина. У плагина нет значка запуска; после установки им полностью управляет AutoJs6.
2. Откройте AutoJs6, зайдите в `Центр плагинов`, найдите `Инструменты изображений` и включите его.
3. В файловом менеджере AutoJs6 найдите любой файл изображения (например `photo.jpg`) и откройте его дополнительное меню.
4. Выберите `Редактировать изображение`, чтобы войти в редактор, или `Преобразовать изображение`, чтобы открыть диалог преобразования.

Панель редактора содержит `Обрезка`, `Повернуть влево`, `Повернуть вправо`, `Точный поворот`, `Отразить по горизонтали`, `Отразить по вертикали`, `Яркость`, `Контрастность`, `Насыщенность`, `Цветовая температура`, `Кисть` и `Текст`. Обрезка имеет свободные, фиксированные и исходные пропорции; точный поворот работает от -45° до +45°. Кисти: карандаш, маркер, мозаика и ластик; текст поддерживает несколько строк, контур и тень. Верхняя панель содержит `Отменить`, `Повторить`, `Сохранить`, а дополнительное меню - `Восстановить оригинал`. `Сохранить` открывает диалог для исходного формата или JPEG / PNG / WebP, качества с потерями и WebP без потерь на Android 11+. Хост публикует новый соседний файл с суффиксом `edited`; исходные метаданные удаляются, оригинал не перезаписывается.

Диалог преобразования предлагает JPEG / PNG / WebP (по умолчанию PNG), качество 1-100 (по умолчанию 92), WebP без потерь на Android 11+ и `Целевой размер файла`, автоматически выбирающий качество JPEG или WebP с потерями. `Изменить размер` предлагает `Исходный`, `Процент` (1-1000), `Длинная сторона` (по умолчанию 1920 px, без увеличения) и `Пользовательский` с необязательной фиксацией пропорций. JPEG заполняет прозрачность белым или черным; PNG автоматически использует индексированную палитру, если результат содержит не более 256 цветов. `Сохранять безопасные метаданные EXIF` по умолчанию выключено и всегда удаляет GPS, встроенные эскизы и метаданные, которые нельзя безопасно проверить. Диалог показывает разрешение, ожидаемый размер и суффикс. `Преобразовать` просит хост опубликовать соседний файл с суффиксом `converted`; `Отменить` или назад не создает файл.

### Поддерживаемые форматы

******

Файловый менеджер показывает действия плагина для файлов со следующими расширениями (и любым MIME-типом `image/*`):

```text
input:  bmp, gif, heic, heif, jpg, jpeg, png, webp (image/*)
output: JPEG (jpg), PNG (png), WebP (webp)
```

Плагин распознает изображения по содержимому и не доверяет расширениям: откроется ли файл, зависит от того, сможет ли Android его декодировать. Анимированные файлы, такие как GIF и анимированный WebP, обрабатываются только по первому кадру; входной и выходной файлы ограничены 256 MiB каждый.

### Частые вопросы

******

**В меню файла нет пунктов `Редактировать изображение` и `Преобразовать изображение`?**

Проверьте по порядку: код версии AutoJs6 не ниже 5269; плагин включен в `Центре плагинов`; расширение файла или его MIME-тип есть в списке поддерживаемых. Если хотя бы одно условие не выполнено, действия в меню не появятся.

**При открытии появляется `Не удалось прочитать информацию об изображении` или экран сразу закрывается?**

Частые причины: файл поврежден или не является настоящим изображением (плагин проверяет содержимое, поэтому переименование расширения не помогает); система не может декодировать формат (HEIC / HEIF обычно не поддерживается до Android 9); файл превышает 256 MiB; вызов пришел не из файлового менеджера AutoJs6. По соображениям безопасности плагин отклоняет вызовы из любых других источников.

**Где сохраняется результат? Перезаписывается ли оригинал?**

Никогда не перезаписывается. Хост публикует результат как новый файл рядом с исходным с суффиксом `edited` или `converted` и автоматически разрешает конфликты имен; исходный файл все время остается для плагина только для чтения.

**Преобразование большого изображения сообщает о нехватке памяти или превышении числа пикселей?**

Размер вывода ограничен трижды: ни одна сторона не может превышать 16384 px, общее число пикселей не может превышать 40 миллионов (40 MP), и все должно уложиться в бюджет памяти устройства. Если источник превышает лимиты, переключите `Изменить размер` на `Процент`, `Длинная сторона` или `Пользовательский`, чтобы уменьшить вывод; при нехватке памяти обычно помогает закрыть другие приложения или еще снизить разрешение.

**Почему отредактированное изображение сохраняется с меньшим разрешением?**

Чтобы редактирование оставалось плавным и стабильным, изображения выше бюджета пикселей редактирования (до примерно 16 MP в зависимости от памяти устройства) уменьшаются перед загрузкой в редактор, и сохраненный результат соответствует холсту редактирования. Если нужно лишь сменить формат или размер, не трогая пиксели, используйте `Преобразовать изображение`: он декодирует точно под выходной размер и этому бюджету не подчиняется.

**Можно ли обработать несколько изображений сразу или сохранить результат в другой каталог?**

Пока нет. Протокол explorer-action v3 поддерживает только действия над одним файлом с выводом рядом, и плагин не может сам выбрать место вывода. Действия с множественным выбором и дополнительные режимы вывода зависят от будущих версий протокола и отслеживаются в плане развития.

### Безопасность

******

Плагин построен по принципу запрета по умолчанию. Все перечисленные меры всегда активны и не могут быть отключены:

- Исходный файл строго только для чтения: плагин открывает вход исключительно через одноразовый content URI только для чтения, выданный хостом, не получает путей файловой системы и не запрашивает разрешений на хранилище и сеть.
- Вывод записывается только в точное место, заранее созданное хостом, и при успехе плагин возвращает лишь идентификатор транзакции; он не может выбрать, создать или вернуть какой-либо другой URI.
- Каждая транзакция вывода одноразовая: использованные идентификаторы записываются постоянно, а повторные или продублированные запросы отклоняются сразу.
- Каждый вызов полностью проверяется: несовпадение версии протокола, источника вызова, идентификатора действия, режима выдачи прав, MIME-типа, отображаемого имени или идентификатора транзакции прерывает выполнение, а права на запись в исходный файл также отклоняются.
- Вход и выход ограничены 256 MiB каждый, выходное разрешение - 16384 px на сторону и 40 MP в сумме, а число закодированных байтов контролируется прямо во время записи.
- Заново закодированный вывод по умолчанию удаляет метаданные источника. Дополнительное безопасное сохранение EXIF использует ограниченный список разрешенных полей; ориентация нормализуется, а GPS-координаты, встроенные миниатюры и метаданные, которые нельзя безопасно проверить, удаляются всегда.

### Интерфейс плагина (для разработчиков)

******

Хост обнаруживает и вызывает плагин по следующим идентификаторам:

```text
service action: org.autojs.plugin.EXPLORER_ACTION
execute action: org.autojs.plugin.EXPLORER_ACTION_EXECUTE
plugin id: image-tools
engine: explorer-action
variant: default
explorer action ids: edit-image / convert-image
input MIME types: image/*
output MIME types: image/jpeg, image/png, image/webp
required host build: 5269
```

Текущая реализация основана на протоколе explorer-action v3: два действия дополнительного меню для одного файла изображения на главной поверхности файлового менеджера, каждое принимает один вход только для чтения и записывает один новый файл через принадлежащую хосту транзакцию вывода create-sibling, возвращая при успехе только идентификатор транзакции. Действия с множественным выбором и на уровне каталогов зависят от будущих версий протокола и отслеживаются в плане развития.


`strings.xml` локализует сведения о плагине и интерфейс редактора и конвертера. Файлы README, CHANGELOG и хостовые `plugin_instruction.md` генерируются из JSON-источников и шаблонов Markdown скриптом `.python/generate_markdown.py`: для изменения документации редактируйте исходники в `.readme` и `.changelog` и запускайте скрипт заново, не редактируя сгенерированные файлы Markdown.
