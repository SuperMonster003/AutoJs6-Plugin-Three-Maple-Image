### 使い始める

独立したホーム画面でローカル画像を表示, 編集, 変換し, 結果を選択した場所に保存. 共通の設定画面で言語, 夜間モード, テーマ色, 4 種類のランチャーアイコンを選択可能.

アプリ ID を `io.github.supermonster003.autojs6.plugin.imageviewer / io.github.supermonster003.autojs6.plugin.imagetools` から `io.github.supermonster003.autojs6.plugin.three.maple.image` に変更. Android では別のアプリとしてインストールされ, 以前のアプリとデータは保持でき, 設定は自動移行されません.

******

### 概要

******

Image Viewer と Image Tools を 3-Maple Image に統合し, 画像の表示, 編集, 形式変換を提供.

表示処理は入力を読み取り専用で使用します. 編集と変換は既定では新しいファイルを作成して元の画像を残し, `元の画像に上書き` を選んだときだけ元の画像を置き換えます (元に戻せます). 独立アプリは Android のファイル選択画面を使用します.

******

### 主な特長

******

- アルバムのホーム: 単独で起動すると端末内の画像をアルバムのグリッドで表示します (カバー, 名前, 枚数). 許可したフォルダーは別のグループになり, メニューの `すべてのフォルダーの内容を表示` でフラットな一覧を開けます. メディアグリッドは 3-6 列 (メニューまたはピンチ), 名前, 更新日時, 撮影日時, サイズ, ランダムでの並べ替えと日ごと / 月ごとのグループ (グループ見出しは上部に残ります) に対応し, `このアルバムのみ` で現在のアルバムだけに適用できます. 日付バブル付きの高速スクロールバーと引っ張って更新にも対応します. アルバム一覧は名前, 更新日時, 撮影日時, 画像の数で並べ替えられます.
- ページ送りビューアーとサムネイルバー: グリッドから開いた画像はアルバム全体を左右にスワイプして閲覧でき, サムネイルバーは現在のページを強調しタップで移動します. 戻るとグリッドは最後に見た画像までスクロールします. 2 本指で画像を回転でき, 指を離すと最も近い 90 度にそろいます (表示のみ. `設定` > `ビューアー` > `2 本指で回転` でオフにできます).
- 回転の保存: ビューアーが元の画像に書き戻せる場合 (アルバムから開いた画像など), 回転後のバーに `保存` が表示されます. JPEG は向きの情報だけを書き換え, 再圧縮せずほかの情報も残します. PNG と WebP は再エンコードします. 保存は `元の画像に上書き` と同じ手順で行われ, 元に戻せます. `設定` > `ビューアー` > `回転後に保存を提案` でオフにできます.
- スライドショーと壁紙: ビューアーのメニューの `スライドショー` は間隔 (1 から 60 秒) ごとにページを送り, ランダムや逆順, ループ, GIF アニメーションを含めるかどうか, 切り替え効果 (なし, フェード, スライド) を選べます. 再生中はボタンが隠れて画面がオンのままになり, タップで一時停止します. `壁紙に設定` は画面と同じ比率の切り抜き枠で表示部分を選び, ホーム画面, ロック画面, または両方に設定します.
- 好みに合わせて: `設定` > `ビューアー` にはジェスチャー (片手ズーム, ダブルタップの拡大率, 最大拡大率, 端をタップしてページ送り, 下にスワイプして閉じる, 左側のスワイプで明るさ調整) と表示 (画面の向き, 黒い背景, 最大の明るさ, システムバーを隠す, 画面をオンのままにする, サムネイル列, 最高画質で表示) の項目があります. `設定` > `アルバムとグリッド` では, アルバムと画像の列数 (縦向きと横向きでそれぞれ), サムネイルの角と間隔, 正方形に切り抜くか, ファイル形式のバッジ, 画像の枚数, アルバム名を 1 行で表示, アニメーションのサムネイル, アルバムのカバー (最新, 最古, またはアルバム内で画像を選んで `その他` > `アルバムのカバーに設定`) を設定できます.
- 詳細情報の表示と位置情報: `詳細情報の表示` をオンにすると, 選んだ情報 (パス, 解像度, ファイルサイズ, 撮影日時と更新日時, カメラ, シャッターと絞り, 焦点距離, ISO, 位置情報) がビューアー下部に文字で表示され, ボタンと一緒に隠れます. 位置情報は既定で表示されず, `位置情報を表示` をオンにしたときだけ座標を表示して地図で開けます. 保存や変換でも `位置情報を残す` にチェックしたときだけ残ります.
- タブレット, 折りたたみ端末, キーボード, スクリーンリーダー: ウィンドウが十分に広いと, ホームの左にアルバム一覧, 右に開いたアルバムを表示します. 折りたたみ, 展開, 回転, 分割画面でも開いたアルバムはそのままで, 横向きではビューアーのサムネイル列が右側に移ります. キーボードやリモコンでグリッドのフォーカスを移動でき (はっきりした枠が付きます), 矢印キーまたは Page Up / Page Down でページ送り, 削除キーで削除します. TalkBack は各画像のファイル名と日付を読み上げ, 設定のグループは見出しとして移動できます.
- 複数選択と整理: グリッドで画像を長押しすると選択を開始し, タップで追加と解除, 長押しのまま指を動かすと範囲を選択できます (上端や下端に近づくと自動でスクロール). `すべて選択` と `選択を反転` にも対応します. 複数の画像をまとめて共有, お気に入り, 移動, コピー, 削除でき, 1 枚の名前の変更や詳細の表示もできます. 移動とコピーではアルバムまたは新しいアルバムを選べ, 最近使ったアルバムが先頭に並びます. 同じ名前の画像があるときは一度だけ確認し (両方を残す, スキップ, 置き換え), 枚数が多いときは進行状況を表示して取り消せます.
- ゴミ箱, 元に戻す, お気に入り: 削除した画像はまずゴミ箱に入り (Android 11 以降はシステムのゴミ箱, Android 7-10 はこのアプリのゴミ箱で 30 日間保持), 削除, 移動, 名前の変更の後は下部の表示から元に戻せます. ホームの右上のメニューの `ゴミ箱` で復元, 完全に削除, 空にすることができます. お気に入りの画像はアルバム一覧の先頭の `お気に入り` アルバムにまとまります. アルバムからビューアーを開いたときは, 上部バーのハートで現在の画像をお気に入りにし, 下部バーの `削除` で削除できます.
- アルバムの整理と検索: アルバム一覧でアルバムを長押しすると複数選択になり, `固定` (`お気に入り` の後に表示), `除外` (このギャラリーだけで非表示, 端末のファイルは変わりません), `非表示` (フォルダーに .nomedia を置き, 他のギャラリーでも表示されなくなります. `すべてのファイルへのアクセス` が必要), アルバムごとの削除 (ゴミ箱へ, 元に戻せます), アルバム名の変更ができます. `設定` の `除外したフォルダー` と `非表示のフォルダー` で確認して戻せます. ホームの検索はアルバム名とファイル名を探し, 開いた画像は検索結果の中で左右にページ送りできます. アルバム内の検索はファイル名で絞り込みます.
- 一括変換: アルバムで画像を複数選択して `その他` > `変換` を選ぶと, 同じ設定 (形式, 品質, 元のサイズ, パーセントまたは長辺, 時計回りの回転, JPEG の背景, 安全な EXIF を残すか) でまとめて変換できます. 新しい画像は `元の名前_converted` として同じアルバムに保存され, 元の画像を上書きしません. 変換中はキャンセルでき, 変換できなかった画像は理由とともに表示され再試行できます. AutoJs6 ファイルマネージャーでも, 画像を複数選択して選択バーの `詳細` から `画像を一括変換` を選べます (このボタンがある AutoJs6 が必要). すべて変換できたときにだけまとめて保存します.
- 必要なときだけ権限を要求: 単独のホームは初回起動時に一度だけ写真へのアクセスを求め, その後は自動で求めません. 許可しなくても `画像を選択`, `フォルダーを選択`, `画像を編集`, `画像を変換` はシステムの選択画面で使えます. Android 14 以降は選択した写真だけの許可 (`選択した写真を管理`) に対応します. `設定` > `ストレージ権限` で再許可, 許可したフォルダー (写真へのアクセスがなくてもアルバムとして表示) と任意の `すべてのファイルへのアクセス` を管理できます. AutoJs6 や他のアプリから画像を開くときは権限を一切求めません.
- アルバムとして表示: AutoJs6 ファイルマネージャーのフォルダーのメニューで `アルバムとして表示` を選ぶと, そのフォルダーの画像をグリッドで表示し, サブフォルダーにも入れます. ホストのセッション経由の読み取り専用で, 権限を求めず, 絶対パスも表示しません.
- 選択した画像だけを開く: AutoJs6 ファイルマネージャーの複数選択モードで, 同じフォルダーから対応画像を最大 128 件選び `画像を表示` をタップします. ビューアーはホストの選択順を保ち, スワイプ対象をそのグループだけに限定します. 選択した各画像は下部バーの `削除` で AutoJs6 のゴミ箱に移動でき, 通知から元に戻せます. 単一のファイルをタップして開いた画像も同じように削除できますが, スワイプで表示した同じフォルダーの他の画像は削除できません.
- タップして閲覧: 対応画像をタップするとビューアーが直接開きます. 1 倍で左右にスワイプすると, 同じフォルダーの対応画像を自然なファイル名順で閲覧できます.
- 自然なジェスチャー: 指を中心にしたピンチズーム (最大 5 倍), 1 本指のパン, ダブルタップで画面フィットとタップ位置を中心とする 2.5 倍ズームを切り替え, 表示を右へ 90° ずつ回転, タップでコントロールの表示/非表示を切り替えて没入表示. ピンチ中とダブルタップ後には現在の倍率が短時間表示されます. `設定` > `ビューアー` でこれらのジェスチャーを調整できます: `片手ズーム` (既定でオン), `端をタップしてページ送り`, `下にスワイプして閉じる`, `左側のスワイプで明るさ調整`, ダブルタップの拡大率 (2.5 倍または実際のピクセル), 最大拡大率 (5 倍, 10 倍, 実際のピクセル).
- 超大型画像も鮮明にズーム: JPEG, PNG, 静止 HEIC/HEIF が端末のテクスチャ上限または制限付きデコード予算を超える場合, 低サンプルのプレビューを表示し, 拡大時は表示中の領域に必要な高解像度タイルだけをデコードします. タイルメモリには上限があり, ページ切り替えやメモリ逼迫時に直ちに解放されます.
- 重要情報がひと目でわかる: オーバーレイのタイトルバーにファイル名と, 複数の画像を開いているときは `3 / 12` 形式のページ番号を表示し, 下部情報バーに MIME タイプ, ファイルサイズ, デコード解像度 (幅 x 高さ) を表示します. Android 8.0 以降でデコーダーから取得できる場合は, デコード後のピクセル深度 (bpp) と出力色空間も表示します.
- 詳細ボトムシート: `詳細` をタップするとドラッグ可能なシートが開き, ファイル名, MIME タイプ, サイズ, 解像度に加えて, EXIF がある場合は撮影日時, 撮影機器, 露出, 向きを確認できます. GPS メタデータがある場合は既定では存在だけを通知します. `設定` > `ビューアー` > `位置情報を表示` をオンにすると撮影地点の座標 (10 進数と度分秒) を表示し, `地図で開く` も使えます. 写真は手動の表示回転より先に EXIF の向きに従って自動的に回転または反転されます.
- 印刷または PDF 保存: 右上のメニューにある `印刷 / PDF に保存` は, EXIF 補正と手動の表示回転を保った現在の画像全体を Android のシステム印刷画面へ送ります. アニメーション GIF ではタップ時に見えているフレームを使用します; ズームやパンで出力は切り抜かれず, プラグインは一時的な画像ファイルや PDF ファイルを作成しません.
- 一般的な形式に標準対応: JPEG ファミリー (JPG / JPEG / JPE / JFIF), PNG, WEBP, BMP, GIF, HEIC, HEIF, AVIF の計 11 拡張子をカバーし, GIF アニメーションは自動ループ再生され, 専用の一時停止/再開コントロールを利用できます.
- 共有と引き渡し: ワンタップでシステムの共有シートを開けます. 右上のメニューの `コピーを共有` では, メタデータ (カメラ, 日時, 位置情報など) を取り除いた元のサイズのコピー, または長辺で縮小したコピーを共有でき, `別のアプリで編集` と `他のアプリ` で画像を他のアプリに渡せます. アプリ一覧からは本プラグイン自身が自動的に除外されます.
- システムの画像ビューアーとしても利用可能: 独立した Android `ACTION_VIEW` エントリーが, ほかのアプリからの読み取り専用画像表示リクエストを安全に受け付けます.
- エディターの上部バーには 元に戻す, やり直し, 比較 (長押しで元の画像を表示), 保存 があり, ツールは `変形`, `調整`, `フィルター`, `描画`, `注釈`, `テキスト` の 6 グループに分かれ, キャンバスは 2 本指で拡大縮小と移動ができます. 変形には切り抜き比率プリセット, 90 度回転と -45° から +45° の微調整回転, 左右/上下反転, `サイズ変更` (パーセント, 長辺, 任意の幅と高さ) があり, 調整には明るさ, コントラスト, 彩度, 色温度, 露出, 色相, ハイライト, シャドウ, シャープ, 周辺減光があり, 調整中はリアルタイムでプレビューします.
- 14 種類のフィルター (`モノクロ`, `セピア`, `ビンテージ`, `フィルム` など) は強さを調整でき, 調整と組み合わせられます. `注釈` では四角形, 楕円, 矢印, 直線をドラッグで描き, 後から移動やサイズ変更ができ, 四角形と楕円は枠のみか塗りつぶしを選べます. キャンバスを長押しすると拡大鏡で色を取得し, HEX 値を表示します.
- ブラシはペン, 蛍光ペン, プライバシー保護モザイク, 消しゴムに対応し, 色と太さを記憶します. テキストは複数行, サイズ, 色, 輪郭, 影, ドラッグ配置に対応します.
- 元に戻すとやり直しは 192 MiB の予算内で最大 8 個の履歴スナップショットを保持します. `元の画像に戻す` 自体も取り消せ, 未保存の変更がある終了時には確認が必要です.
- 保存ダイアログでは元の形式に従うか JPEG, PNG, WebP を選び, 非可逆画質を調整し, Android 11+ ではロスレス WebP を有効にできます. 既定では新しいファイルとして保存してファイル名を表示し, `元の画像に上書き` (形式は維持) と `撮影情報を残す` (位置情報は既定で削除. `位置情報を表示` がオンなら `位置情報を残す` も選べます) も選べます. 上書きは通知から 1 回だけ元に戻せます.
- コンバーターは JPEG / PNG / WebP, 画質 1-100 (既定 92), JPEG と非可逆 WebP の目標ファイルサイズ, Android 11+ のロスレス WebP, 256 色以下での自動インデックス PNG 最適化に対応します.
- サイズは `元のサイズ`, `パーセント` (1-1000), 縦横比固定可能な `カスタム`, 既定 1920 px で拡大しない `長辺` の 4 モードです. JPEG は透明部分を白または黒で塗りつぶせます.
- 変換ツールと一括変換は同じフォームを使い, 下部に出力解像度, 推定サイズ, 保存されるファイル名をリアルタイム表示します. 変換ツールでは `元の画像に上書き` も選べます. 安全な EXIF 保持は既定で無効です. 有効時も上限付きカメラ項目だけを保持し, 向きを正規化して 埋め込みプレビューを常に削除します. GPS は既定で削除され, `位置情報を表示` がオンなら `位置情報を残す` を選べます.
- 構成変更でもキャンバス, ダイアログの下書き, 元に戻す/やり直し履歴, 実行中タスクを保持します. AutoJs6 から呼び出した場合, 新しいファイルも上書きもホストセッション経由で書き込まれます. いったん保留して読み戻しで確認し, 成功してから公開するため, 失敗しても書きかけのファイルは残りません. 上書きは 8 秒以内なら元に戻せます.

### インストールと使い方

******

開始する前に次の要件を確認してください:

```text
host app: AutoJs6 (org.autojs.autojs6)
minimum host build: 5352
minimum android: 7.0 (API 24)
plugin package: io.github.supermonster003.autojs6.plugin.three.maple.image
```

インストールから最初の画像表示まで 4 ステップです:

1. 3-Maple Image を単独で起動すると端末内のアルバムを閲覧できます (初回起動時に一度だけ写真へのアクセスを求めます). 右上のメニューからは引き続きローカル画像を選んで表示, 編集, 変換し, 結果を選択した場所に保存できます.
2. AutoJs6 を開いて `プラグインセンター` に入り, `3-Maple Image` を見つけて有効にします.
3. AutoJs6 ファイルマネージャーで対応する任意の画像ファイル (例: `screenshot.png`) を探します.
4. ファイルをタップすると, 画像が専用ビューアーで開きます. フォルダーのメニューで `アルバムとして表示` を選ぶと, そのフォルダーの画像をグリッドで表示します.

ビューアーでは: 1 倍で左右にスワイプすると, 同じフォルダーの前または次の対応画像へ移動します. ピンチ操作で指の位置を中心にズームし (1 倍から 5 倍), 1 本指のドラッグでパンし, ダブルタップで画面フィットとタップ位置を中心とする 2.5 倍ズームを切り替えられます. ピンチ中とダブルタップ後には現在の倍率が短時間表示されます. `回転` で現在の表示だけを 90° ずつ回転できます. ズームは維持され, 右上のメニューの `ズームをリセット` で元の向きと画面フィットの両方に戻ります. GIF アニメーションにはフローティングの `アニメーションを一時停止` / `アニメーションを再開` ボタンが表示され, 静止画像には表示されません. 画像のタップでオーバーレイバーの表示を切り替え, `詳細` をタップするとファイル情報と EXIF 項目のボトムシートが開きます. `共有` と `他のアプリ` は最初に開いた画像で使用できます. セッションだけで開いた隣接ページは転送可能な content URI を意図的に持たないため, これらの操作は無効になります. スタンドアロンのホームや他のアプリから開いた画像では `編集` も使え, エディターを開いて結果を保存できます. ホストからの入口と隣接ページでは `編集` は表示されません. アルバムから開いた画像では, 上部バーのハートで現在の画像をお気に入りにし, 下部バーの `削除` でゴミ箱へ移動でき (元に戻せます), `他のアプリ`, `名前を変更`, `移動`, `コピー` は右上のメニューにあります. 元の画像に書き戻せる場合, 回転後のバーに `保存` が表示されます. AutoJs6 から開いた場合, タップして開いた画像と選択して開いた各画像では下部バーに `削除` が表示され (AutoJs6 のゴミ箱へ移動, 元に戻せます), `他のアプリ` は右上のメニューに移ります. 右上のメニューには `スライドショー`, `壁紙に設定`, `コピーを共有`, `別のアプリで編集` (現在の画像を他のアプリに渡せる場合) もあります. ジェスチャーと表示は `設定` > `ビューアー` で調整できます.

### 対応形式

******

ファイルマネージャーの表示アクションは次の拡張子に正確に一致します:

```text
AVIF, BMP, GIF, HEIC, HEIF, JFIF, JPE, JPEG, JPG, PNG, WEBP
```

JFIF と JPE は JPEG ファミリーの別名拡張子です. HEIC と HEIF には Android 9 以降, AVIF には Android 12 以降が必要です. ビューアーは小さなローカルデコーダー能力プローブも実行し, プラットフォームデコーダーを利用できなければ専用のメッセージを表示します. 独立した `ACTION_VIEW` エントリーは `image/*` MIME タイプでリクエストを受け付けるため, 上記の一覧に限定されません. 1 ファイルの上限は 8 TiB で, 実際のデコード対応は Android プラットフォームと Glide に依存します.

### よくある質問

******

**単独で起動すると写真へのアクセスを求められるのはなぜ? 拒否しても使える?**

アルバムのホームには端末内の画像一覧が必要なため, 単独での初回起動時に一度だけ求めます (Android 13 以降は写真と動画, それ以前はストレージ). その後は自動で求めません. 許可しなくても `画像を選択`, `フォルダーを選択`, `画像を編集`, `画像を変換` はシステムの選択画面で使えます. 後からホームのボタンまたは `設定` > `ストレージ権限` で許可でき, システムがダイアログを表示しなくなるとボタンは `アプリ設定を開く` に変わります. AutoJs6 や他のアプリから画像を開くときは権限を一切求めません.

**Android 14 以降で一部の写真だけを許可したら, ほかのアルバムが表示されないのはなぜ?**

部分的なアクセスでは, システムの写真選択ツールで選んだ写真だけが公開されるため, その写真を含むアルバムだけが表示されます. ホーム上部の `選択した写真を管理` で選択を変更するか, `設定` > `ストレージ権限` で完全なアクセスを許可し直してください.

**`すべてのファイルへのアクセス` は何のため? オンにする必要はある?**

ありません. システム設定ページを開く任意の詳細スイッチで, アルバムの閲覧には写真へのアクセスだけで足ります. オンにすると, 他のアプリが保存した画像の削除, 移動, 名前の変更でバッチごとのシステムの確認が出なくなります (Android 12 以降は `設定` > `ストレージ権限` の `メディアの管理` だけをオンにしても同じです). アルバムを非表示にする (フォルダーに .nomedia を書き込む) にはこのスイッチが必要です. システム設定でいつでもオフにできます.

**削除した画像はどこへ行く? 削除や移動のときにシステムの確認が出るのはなぜ?**

削除した画像はまずゴミ箱に入り, ホームの右上のメニューの `ゴミ箱` から復元できます. Android 11 以降はシステムのゴミ箱を使い, 約 30 日後にシステムが消去します. Android 7-10 ではこのアプリのゴミ箱を使い, 30 日間保持し, 空き容量の 10 分の 1 (最大 2 GiB) まで使用し, アプリのアンインストール時に一緒に消去されます. `設定` で `ゴミ箱` をオフにすると, 削除の前に確認が出て元に戻せなくなります. Android 11 以降で他のアプリが保存した画像を変更するにはシステムの確認が必要で, 確認はバッチごとに一度です. `メディアの管理` (Android 12 以降) または `すべてのファイルへのアクセス` をオンにすると毎回の確認はなくなります.

**`除外` と `非表示` の違いは何ですか?**

`除外` はこのギャラリーだけに影響します. フォルダーの画像がアルバム一覧, `すべての画像`, `お気に入り`, 検索に表示されなくなり, 端末上のファイルは変わりません. `設定` > `除外したフォルダー` で戻せます. `非表示` はフォルダーに .nomedia ファイルを置くため, システムや他のギャラリーアプリでも画像が表示されなくなります (ファイルは削除されません). Android 11 以降では先に `すべてのファイルへのアクセス` が必要で, `設定` > `非表示のフォルダー` で再表示できます. どちらも AutoJs6 のファイルマネージャーの表示には影響しません.

**ファイルのメニューに `画像を編集` と `画像を変換` が表示されない?**

次の順に確認してください: AutoJs6 のバージョンコードが 5352 以上か; プラグインが `プラグインセンター` で有効になっているか; ファイルの拡張子または MIME タイプが対応リストに含まれているか. どれかひとつでも満たさないと, メニューアクションは表示されません. 3.2.0 以降, 本プラグインは explorer-action プロトコル 24 を宣言します. 対応していない AutoJs6 では本プラグインのメニュー操作がすべて表示されません (`画像を表示` や `アルバムとして閲覧` を含む). AutoJs6 を更新してください. アルバムと単体ホーム画面からの編集と変換には影響しません. 3.1.2 以前には不備があり, 3 つの条件を満たしていてもこの 2 つは表示されませんでした. 3.2.0 に更新してください.

**開くと `画像情報を読み取れません` と表示される, または画面が一瞬で閉じる?**

ファイルを現在読み取れない状態です. 移動や削除をされた, 共有元のアプリがアクセスを取り消した, または内容が拡張子と一致しない (破損したファイルなど) 可能性があります. 現在の場所から開き直すか, 元のアプリから共有し直してください.

**処理結果はどこに保存される? 元の画像は上書きされる?**

既定では上書きしません. AutoJs6 から呼び出した場合, 結果は新しいファイル (`名前_edited` または `名前_converted`) として元のファイルの隣に保存されます. アルバムや単体ホーム画面から処理した場合は, 完了後に保存先を選びます. 保存ダイアログまたは変換ページで `元の画像に上書き` をオンにしたときだけ元の画像を置き換え, 形式は変わりません. 置き換えた後は通知から 1 回だけ元に戻せます: AutoJs6 から呼び出した場合はホストが前のバージョンを保持し, 8 秒以内なら元に戻せます. アルバムとホーム画面ではプラグインが次の上書きまでバックアップを 1 つ保持します (256 MiB を超える画像は先に元に戻せないことを知らせます).

**写真の位置情報は表示されたり保存されたりする?**

既定ではどちらもありません: ビューアーは位置情報があることだけを示し, 編集, 変換, 一括変換, `コピーを共有` で作られる画像からは位置情報が削除されます (`共有` は元のファイルをそのまま送ります). 必要なときは `設定` > `ビューアー` > `位置情報を表示` をオンにしてください: 詳細に撮影地点の座標が表示され, `地図で開く` が使えます (座標は選んだ地図アプリに渡されます. 本プラグインはネットワーク権限を持ちません). 保存と変換では `位置情報を残す` のチェックボックスが表示され, 元の画像に上書きする場合も含めて既定ではオフです.

**AutoJs6 から開いた画像は削除できる?**

AutoJs6 でタップして開いた画像, または選択して開いた各画像は削除できます. 下部バーの `削除` で AutoJs6 のゴミ箱 (システムのゴミ箱ではありません) に移動し, 通知から元に戻せるほか, 後から AutoJs6 のゴミ箱ページで復元することもできます. スワイプで表示した同じフォルダーの他の画像と `アルバムとして閲覧` の画像は削除できません. AutoJs6 が許可するのは選択したファイルだけだからです. この機能にはプロトコル 24 に対応した AutoJs6 が必要です.

**大きな画像の変換でメモリ不足やピクセル数超過と表示される?**

出力サイズには三重の制限があります: 一辺は 16384 px 以下, 総ピクセル数は 4000 万 (40 MP) 以下, さらに端末のメモリ予算内に収まる必要があります. 元画像が制限を超える場合は `サイズ変更` を `パーセント`, `長辺`, `カスタム` のいずれかに切り替えて出力を縮小してください. メモリ不足は他のアプリを終了するか解像度をさらに下げれば通常解決します.

**編集後に保存した画像の解像度が下がっているのはなぜ?**

編集を滑らかで安定した動作に保つため, 編集ピクセル予算 (端末メモリに応じて最大約 16 MP) を超える画像はダウンサンプリングしてからエディターに読み込まれ, 保存結果は編集キャンバスの解像度になります. ピクセルを触らず形式やサイズだけ変えたい場合は `画像を変換` を使ってください. こちらは出力サイズで正確にデコードするため, この予算の制限を受けません.

**複数の画像を一括処理したり, 結果を別のディレクトリに保存したりできる?**

変換は一括でできます: アルバムで画像を複数選択して `その他` > `変換` を選ぶと, 新しい画像は同じアルバムに保存されます. AutoJs6 ファイルマネージャーでは画像を複数選択して `詳細` > `画像を一括変換` を選ぶと (このボタンがある AutoJs6 が必要), 元の画像の隣に保存されます. 編集は 1 枚ずつ処理します. 独立したホーム画面で 1 枚を編集または変換するときは保存先を選択でき, AutoJs6 からの操作では元の画像と同じフォルダに新しいファイルを作成します.

### セキュリティ

******

プラグインはデフォルト拒否の原則で構築されています. 次の対策はすべて常時有効で, 無効化できません:

- 表示処理は入力を読み取り専用で使用します. 編集と変換は既定では新しいファイルを作成して元の画像を残し, `元の画像に上書き` を選んだときだけ元の画像を置き換えます (元に戻せます). 独立アプリは Android のファイル選択画面を使用します.
- AutoJs6 (`画像を表示`, `アルバムとして表示`) や他のアプリから画像を開くときは実行時権限を一切求めません. 単独のホームが自動で写真へのアクセスを求めるのは最大一度だけで, `すべてのファイルへのアクセス` と `メディアの管理` はユーザーがシステム設定でオンにした場合だけ有効になります.
- プラグインはネットワーク権限 (`INTERNET`) を宣言しません. アルバム, サムネイル, 画像の詳細は端末内で読み取られ, 端末の外へ出ることはありません.
- 削除, 移動, 名前の変更, 非表示, 元の画像への上書きは, ユーザーが明示的に操作したときだけ実行されます. AutoJs6 から開いた場合は選択したファイルだけを削除でき (AutoJs6 のゴミ箱へ移動), 他のアプリから開いた画像では削除, 移動, 名前の変更, 非表示は表示されません.

### プラグインインターフェース (開発者向け)

******

ホストは次の識別情報でプラグインを検出して呼び出します:

```text
service action: org.autojs.plugin.EXPLORER_ACTION
execute action: org.autojs.plugin.EXPLORER_ACTION_EXECUTE
plugin id: three-maple-image
engine: explorer-action
variant: default
explorer action id: view-image
protocol version: 24
MIME type: Explorer: avif/bmp/gif/heic/heif/jfif/jpe/jpeg/jpg/png/webp; ACTION_VIEW: image/*
required host build: 5352
```

現在の実装は explorer-action プロトコルバージョン 24 に基づきます: プライマリーアクション `view-image` は単一ファイル対象, 読み取り専用アクセス, `readSiblings`, `targetTrash` を宣言します. ホストセッションが公開するのは直下の隣接ファイルだけです. プラグインは対応形式で読み取り可能かつシンボリックリンクでない画像を残し, 自然なファイル名順に並べ, 選択画像の周囲に最大 128 ページの有界ウィンドウを維持します. 選択ツールバーアクション `view-images` は `readSiblings` なしで複数ファイルと `targetTrash` を宣言し, 同じ親の対応画像を 1 件から 128 件まで受け付け, ホストの選択順を維持して明示的に許可された対象だけを渡します. `targetTrash` により, ビューアーはリクエスト対象を 1 件ずつホストのゴミ箱へ移動でき, 移動ごとに元に戻せるバッチになります. 隣接ファイルは対象外です. `edit-image` と `convert-image` は `ACCESS_MANAGE_TARGET` を宣言します. 新しいファイルはセッション経由で保留, 読み戻し確認の後に公開され, 上書きはホストの対象置換を使い, `undoTargetReplacement` で 1 回だけ元に戻せます. 詳細, 移動, 名前変更は引き続きホストの機能です. プラグインがない場合, ホストは読み取り専用の外部 `ACTION_VIEW` リクエストにフォールバックします. 3 つ目の選択ツールバーアクション `convert-images` は複数ファイルと `ACCESS_CREATE_IN_PARENT` を宣言します. 画像ごとに元のディレクトリへ新しいファイルを作成して読み戻しで確認し, 1 つの出力バッチとしてまとめて公開します. 1 枚でも失敗するとすべてロールバックします.
