### مقدمة

******

Image Tools (أدوات الصور) هو ملحق لمعالجة الصور مخصص لمدير ملفات AutoJs6. بعد تفعيله يظهر لكل ملف صورة في مدير الملفات إجراءان في القائمة المنبثقة: `تحرير الصورة` يفتح محررا بلوحة رسم وشريط أدوات للتعديلات اليومية (اقتصاص, تدوير, ضبط الألوان, رسم), و `تحويل الصورة` يفتح مربع حوار يحفظ الصورة بصيغة JPEG أو PNG أو WebP مع إمكانية تغيير حجمها.

تحفظ النتيجة دائما كملف جديد بجوار الملف الأصلي (يضاف إلى اسمه اللاحقة `edited` أو `converted`). يبقى الملف الأصلي للقراءة فقط طوال الوقت ولا يتم تعديله أو استبداله أو حذفه أبدا. لا يطلب الملحق أي أذونات تخزين أو شبكة, ولا يمكنه الوصول إلا إلى ملف إدخال واحد وموقع إخراج واحد يصرح بهما المضيف.

******

### أبرز الميزات

******

- يوفر المحرر إعدادات مسبقة لنسب الاقتصاص, وتدويرا بزاوية 90 درجة وتدويرا دقيقا من -45° إلى +45°, وقلبا أفقيا ورأسيا, وضبط السطوع والتباين والتشبع وحرارة اللون, وفرشا ونصا منسقا مع معاينة حية.
- تشمل أنواع الفرشاة القلم وقلم التمييز وفسيفساء الخصوصية والممحاة مع تذكر اللون والسماكة; ويدعم النص عدة أسطر والحجم واللون والحد والظل وتحديد الموضع بالسحب.
- يحتفظ التراجع والإعادة بما يصل إلى 8 لقطات سجل ضمن ميزانية 192 MiB; ويمكن التراجع عن `استعادة الصورة الأصلية` نفسها, ويتطلب الخروج مع تغييرات غير محفوظة تأكيدا.
- يمكن لمربع حوار حفظ المحرر اتباع تنسيق المصدر أو اختيار JPEG أو PNG أو WebP وضبط جودة الضغط مع فقدان وتفعيل WebP بلا فقدان على Android 11+; وينشر المضيف ملفا جديدا مجاورا بدلا من استبدال المصدر.
- يدعم المحول JPEG / PNG / WebP والجودة 1-100 (الافتراضي 92) وحجم الملف المستهدف لـ JPEG و WebP مع فقدان و WebP بلا فقدان على Android 11+ والتحسين التلقائي لـ PNG المفهرس عندما لا تتجاوز الصورة 256 لونا.
- تتضمن أوضاع الحجم الأربعة `الأصلي` و `النسبة المئوية` (1-1000) و `مخصص` مع قفل النسبة و `الضلع الطويل` (1920 بكسل افتراضيا ومن دون تكبير); ويمكن لـ JPEG ملء الشفافية بالأبيض أو الأسود.
- يعرض مربع الحوار الدقة والحجم المتوقع في الوقت الفعلي. يكون الاحتفاظ الآمن ببيانات EXIF معطلا افتراضيا; وعند تشغيله يحتفظ بحقول كاميرا محدودة ويطبع الاتجاه ويزيل دائما GPS والمعاينات المضمنة.
- تحافظ تغييرات الإعداد على اللوحة ومسودات مربعات الحوار وسجل التراجع/الإعادة والمهام الجارية; ويظل كل إجراء يستخدم إدخالا واحدا للقراءة فقط ومعاملة إخراج مجاورة واحدة يملكها المضيف وتستخدم مرة واحدة.

### التثبيت والاستخدام

******

تحقق من المتطلبات التالية قبل البدء:

```text
host app: AutoJs6 (org.autojs.autojs6)
minimum host build: 5269
minimum android: 7.0 (API 24)
plugin package: io.github.supermonster003.autojs6.plugin.imagetools
```

من التثبيت إلى أول صورة معالجة 4 خطوات فقط:

1. نزل ملف APK الخاص بالملحق وثبته. لا يملك الملحق أيقونة تشغيل, وبعد التثبيت يديره AutoJs6 بالكامل.
2. افتح AutoJs6 وادخل إلى `مركز الاضافات`, ثم ابحث عن `أدوات الصور` وفعله.
3. في مدير ملفات AutoJs6 حدد أي ملف صورة (مثل `photo.jpg`) وافتح قائمته المنبثقة.
4. اختر `تحرير الصورة` لدخول المحرر, أو اختر `تحويل الصورة` لفتح مربع حوار التحويل.

يوفر شريط المحرر `اقتصاص` و `تدوير لليسار` و `تدوير لليمين` و `تدوير دقيق` و `قلب أفقي` و `قلب رأسي` و `السطوع` و `التباين` و `التشبع` و `حرارة اللون` و `فرشاة` و `نص`. يتضمن الاقتصاص نسبا حرة وثابتة ونسبة الأصل; ويتراوح التدوير الدقيق من -45° إلى +45°. أنواع الفرشاة هي القلم وقلم التمييز والفسيفساء والممحاة; ويدعم النص عدة أسطر وحدا وظلا. يوفر الشريط العلوي `تراجع` و `إعادة` و `حفظ`, وتوفر القائمة الإضافية `استعادة الصورة الأصلية`. يفتح `حفظ` مربع حوار لاتباع تنسيق المصدر أو اختيار JPEG / PNG / WebP وضبط جودة الضغط مع فقدان وتفعيل WebP بلا فقدان على Android 11+. ينشر المضيف ملفا مجاورا جديدا باللاحقة `edited`; تزال بيانات المصدر الوصفية ولا يستبدل الملف الأصلي أبدا.

يوفر مربع حوار التحويل JPEG / PNG / WebP (PNG افتراضيا) والجودة 1-100 (الافتراضي 92) و WebP بلا فقدان على Android 11+ و `حجم الملف المستهدف` الذي يختار الجودة تلقائيا لـ JPEG أو WebP مع فقدان. يوفر `تغيير الحجم` أوضاع `الأصلي` و `النسبة المئوية` (1-1000) و `الضلع الطويل` (1920 بكسل افتراضيا ومن دون تكبير) و `مخصص` مع قفل اختياري للنسبة. يمكن لـ JPEG ملء الشفافية بالأبيض أو الأسود; ويستخدم PNG لوحة مفهرسة تلقائيا إذا لم تتجاوز النتيجة 256 لونا. يكون `الاحتفاظ ببيانات EXIF الآمنة` معطلا افتراضيا ويزيل دائما GPS والمعاينات المضمنة والبيانات التي لا يمكن فحصها بأمان. يعرض مربع الحوار الدقة والحجم المتوقع واللاحقة. يطلب `تحويل` من المضيف نشر ملف مجاور باللاحقة `converted`; ولا ينشئ `إلغاء` أو الرجوع أي ملف.

### التنسيقات المدعومة

******

يعرض مدير الملفات إجراءات الملحق للملفات ذات الامتدادات التالية (وأي نوع MIME من فئة `image/*`):

```text
input:  bmp, gif, heic, heif, jpg, jpeg, png, webp (image/*)
output: JPEG (jpg), PNG (png), WebP (webp)
```

يتعرف الملحق على الصور من محتواها ولا يثق بالامتدادات: نجاح الفتح يعتمد على قدرة Android على فك ترميز الملف. الملفات المتحركة مثل GIF و WebP المتحرك تعالج بإطارها الأول فقط; وحد ملف الإدخال وملف الإخراج 256 MiB لكل منهما.

### الأسئلة الشائعة

******

**لا يظهر `تحرير الصورة` و `تحويل الصورة` في قائمة الملف?**

تحقق بالترتيب: رمز إصدار AutoJs6 لا يقل عن 5269; الملحق مفعل في `مركز الاضافات`; امتداد الملف أو نوع MIME الخاص به ضمن قائمة الدعم. إن لم يتحقق أي شرط منها فلن تظهر إجراءات القائمة.

**يظهر `تعذر قراءة معلومات الصورة` عند الفتح أو تغلق الشاشة فورا?**

الأسباب الشائعة: الملف تالف أو ليس صورة حقيقية (يفحص الملحق المحتوى فتغيير الامتداد وحده لا يجدي); النظام لا يستطيع فك ترميز التنسيق (HEIC / HEIF غير مدعوم عادة قبل Android 9); حجم الملف يتجاوز 256 MiB; أو أن الاستدعاء لم يأت من مدير ملفات AutoJs6. لأسباب أمنية يرفض الملحق أي مصدر استدعاء آخر.

**أين تحفظ النتيجة? وهل يستبدل الملف الأصلي?**

لا يستبدل أبدا. ينشر المضيف النتيجة كملف جديد بجوار الملف الأصلي باللاحقة `edited` أو `converted` ويحل تعارضات الأسماء تلقائيا; ويبقى الملف الأصلي للقراءة فقط بالنسبة إلى الملحق طوال الوقت.

**يبلغ تحويل صورة كبيرة عن نفاد الذاكرة أو تجاوز عدد البكسلات?**

حجم الإخراج مقيد بثلاثة حدود: لا يتجاوز أي ضلع 16384 px, ولا يتجاوز إجمالي البكسلات 40 مليونا (40 MP), ويجب أن يبقى ضمن ميزانية ذاكرة الجهاز. إذا تجاوز المصدر الحدود فبدل `تغيير الحجم` إلى `النسبة المئوية` أو `الضلع الطويل` أو `مخصص` لتصغير الإخراج; ونفاد الذاكرة يحل عادة بإغلاق التطبيقات الأخرى أو خفض الدقة أكثر.

**لماذا تحفظ الصورة المحررة بدقة أقل?**

للحفاظ على سلاسة التحرير واستقراره, الصور التي تتجاوز ميزانية بكسلات التحرير (حتى نحو 16 MP حسب ذاكرة الجهاز) يخفض حجمها قبل تحميلها في المحرر, وتطابق النتيجة المحفوظة لوحة التحرير. إن أردت تغيير التنسيق أو الحجم فقط دون لمس البكسلات فاستخدم `تحويل الصورة`: فهو يفك الترميز بدقة وفق حجم الإخراج ولا يخضع لهذه الميزانية.

**هل يمكن معالجة عدة صور دفعة واحدة أو حفظ النتيجة في مجلد آخر?**

ليس بعد. لا يدعم بروتوكول explorer-action v3 سوى إجراءات الملف الواحد مع إخراج مجاور, ولا يستطيع الملحق اختيار موقع الإخراج بنفسه. إجراءات التحديد المتعدد وأوضاع الإخراج الإضافية تعتمد على إصدارات مستقبلية من البروتوكول وتتابع في خارطة الطريق.

### الأمان

******

بني الملحق على مبدأ الرفض الافتراضي. جميع التدابير التالية مفعلة دائما ولا يمكن تعطيلها:

- الملف الأصلي للقراءة فقط بصرامة: يفتح الملحق الإدخال حصرا عبر content URI للقراءة فقط يمنح لمرة واحدة من المضيف, ولا يستلم مسارات نظام الملفات, ولا يطلب أذونات تخزين أو شبكة.
- يكتب الإخراج فقط في الموقع المحدد الذي أنشأه المضيف مسبقا, وعند النجاح لا يعيد الملحق سوى معرف المعاملة; ولا يمكنه اختيار أو إنشاء أو إعادة أي URI آخر.
- كل معاملة إخراج تستخدم لمرة واحدة: تسجل المعرفات المستخدمة بشكل دائم, وترفض الطلبات المكررة أو المعادة فورا.
- يتحقق من كل استدعاء بالكامل: أي عدم تطابق في إصدار البروتوكول أو مصدر الاستدعاء أو معرف الإجراء أو وضع منح الأذونات أو نوع MIME أو الاسم المعروض أو معرف المعاملة يوقف التنفيذ, كما يرفض أي منح لصلاحية الكتابة على الملف الأصلي.
- الإدخال والإخراج محدودان بـ 256 MiB لكل منهما, ودقة الإخراج محدودة بـ 16384 px للضلع الواحد و 40 MP إجمالا, ويراقب عدد البايتات المرمزة أثناء الكتابة مباشرة.
- يزيل الإخراج المعاد ترميزه بيانات المصدر الوصفية افتراضيا. يستخدم الاحتفاظ الاختياري ببيانات EXIF الآمنة قائمة سماح محدودة; ويطبع الاتجاه, بينما يزال دائما موقع GPS والمعاينات المضمنة والبيانات الوصفية التي لا يمكن فحصها بأمان.

### واجهة الملحق (للمطورين)

******

يكتشف المضيف الملحق ويستدعيه عبر المعرفات التالية:

```text
service action: org.autojs.plugin.EXPLORER_ACTION
execute action: org.autojs.plugin.EXPLORER_ACTION_EXECUTE
plugin id: image-tools
engine: explorer-action
variant: default
explorer action ids: edit-image / convert-image
input MIME types: image/*
output MIME types: image/jpeg, image/png, image/webp
required host build: 5269
```

يعتمد التنفيذ الحالي على بروتوكول explorer-action v3: إجراءان في القائمة المنبثقة لملف صورة واحد على السطح الرئيسي لمدير الملفات, يستلم كل منهما إدخالا واحدا للقراءة فقط ويكتب ملفا جديدا واحدا عبر معاملة إخراج create-sibling يملكها المضيف, ولا يعيد عند النجاح سوى معرف المعاملة. إجراءات التحديد المتعدد وإجراءات مستوى المجلد تعتمد على إصدارات مستقبلية من البروتوكول وتتابع في خارطة الطريق.

* `تحسين` توسيع استعادة الحالة وفرض حدود الذاكرة / الإخراج وتغطية الانحدار إلى 23 حزمة / 99 اختبارًا
* `تحسين` تحديث ملفات README وتعليمات المضيف بعشر لغات من مصادر مشتركة وإضافة ثلاث لقطات شاشة حقيقية خالية من البيانات الشخصية
* `تحسين` التحقق أثناء البناء لمنع إدخال تبعيات أصلية غير مقصودة, مع تقرير JSON

### هيكل الموارد

******

```text
.readme/lang_*.json
.readme/template_plugin_instruction.md
.changelog/lang_*.json
.python/generate_markdown.py
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/values-*/strings.xml
app/src/main/res/raw-*/plugin_instruction.md
```

يوطن `strings.xml` معلومات الملحق وواجهة المحرر والمحول. تولد ملفات README و CHANGELOG و `plugin_instruction.md` الخاصة بالمضيف من مصادر JSON وقوالب Markdown بواسطة السكربت `.python/generate_markdown.py`: لتعديل الوثائق حرر المصادر داخل `.readme` و `.changelog` ثم أعد تشغيل السكربت, ولا تحرر ملفات Markdown المولدة مباشرة.
